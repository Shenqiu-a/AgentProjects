# 数据库与测试数据

2026-10-14 已实际连接本机 `localhost:5432/after_sales`，通过 Flyway 执行 V2—V5，创建 18 张业务表并导入本地样例。另有 `flyway_schema_history` 版本表，共 19 张表。现有 V1 保持不变。当前操作没有修改 `after_sales_eval` 或其他数据库。

## 1. 在 pgAdmin 中查看

展开 **PostgreSQL 18 → 数据库 → after_sales → 架构/Schemas → public → 表/Tables**，右键“表”并刷新。右键具体表 → 查看/编辑数据 → 所有行。

查询工具顶部的数据库必须是 **after_sales**；只选中左侧库名，不会把已经打开的其他数据库查询窗口切换过来。

在连接 after_sales 的查询窗口执行 [数据库查询示例](../scripts/inspect-database.sql)。其中包含版本、订单、工单和知识分块查询，可按语句单独选中执行。

## 2. 表与代码开发顺序

| 阶段 | 表 | 用途与后续实现 |
|---|---|---|
| S1 基础业务 | app_user | BCrypt 账号；实现 UserRepository、UserDetailsService、SecurityFilterChain 后才能用账号登录 |
| S1 基础业务 | product、policy_rule、customer_order | 商品、政策版本、订单；先用 JdbcClient/JdbcTemplate 实现本人订单查询，再写 Java 资格判断服务 |
| S2 文档与 RAG | knowledge_document | 文件元信息、状态及当前发布代次 |
| S2 文档与 RAG | document_ingestion | 导入阶段、租约、进度和模型配置；实现文件解析、分块、Embedding、发布的 worker |
| S2 文档与 RAG | knowledge_chunk | 原文分块、字符区间、向量与元数据；实现限定命名空间的检索 |
| S3 会话与 Agent | conversation、chat_message | 用户会话、可见消息；加事务和会话锁分配 sequence |
| S3 会话与 Agent | agent_run | 状态、检查点、执行次数、版本及租约；实现执行器、恢复、取消 |
| S3 可观测性 | tool_call、run_event | 工具审计与 SSE 可回放事件；必须先落库，再推送事件 |
| S4 人工确认与工单 | confirmation、ticket、ticket_status_history | 确认草稿、维修工单和状态历史；实现本人确认及事务内建单、管理员状态推进 |
| S4 幂等 | idempotency_record | 同一用户/操作/key 的请求摘要与响应快照，保留至少 24 小时 |
| S5 评测 | evaluation_job、evaluation_case_result | 评测任务配置和逐案例断言；正式评测切换独立库，不影响开发数据 |

表结构来源于需求文档的 18 表设计，完整列定义见 `backend/src/main/resources/db/migration/`。UUID 为主键，业务编号另加唯一约束，时间使用 `timestamptz`，金额使用 `numeric(12,2)`，结构化状态快照使用 JSONB。

`customer_order.product_category` 是有意增加的冗余列：两组复合外键保证订单商品类别与政策类别相同。分块增加模型、维度、命名空间字段，通过复合外键绑定导入任务，防止将其他模型的向量混进同一任务。

## 4. 测试账号密码

密码由本地工具用 SecureRandom 随机生成。明文仅写入 **`data/local/test-accounts.properties`**，该目录已被 `.gitignore` 排除；数据库只存 BCrypt hash（cost 10）。用本地编辑器打开该文件即可查看 `alice.password`、`bob.password`、`admin.password`。

这些是应用测试账号，与连接 PostgreSQL 的 `postgres` 账号不同。登录接口和数据库用户认证适配器还没有实现，当前 Spring Security 默认登录页不会自动读取这些账号。

保留该本地文件以便重复初始化时验证原密码。不要把它提交到仓库或用于生产。如果数据库已有相同用户名但 UUID 或密码不同，初始化事务会报错回滚，不会重置密码。

## 5. 在本机重复执行 / 在另一台电脑重建

前提：JDK 21、Maven、已安装 pgvector 的 PostgreSQL，以及存在的 `after_sales` 数据库。准备当前电脑自己的项目根目录 `.env`，账号须有建表权限。脚本仅允许本机 `after_sales`；不支持远端生产库或评测库。

从项目根目录执行：

```powershell
# 迁移 + 少量开发数据 + 校验。可重复执行；不删除数据，不重置已有密码。
.\scripts\Initialize-Database.ps1

# 只应用 Flyway 迁移，不导入测试账号或样例。
.\scripts\Initialize-Database.ps1 -Action migrate

# 校验当前样例和约束；约束探测使用事务，结束后全部回滚。
.\scripts\Initialize-Database.ps1 -Action verify
```

默认由 Maven 解析 backend 的运行依赖，生成 `backend/target/database-tool-classpath.txt`，再通过 Java source launcher 运行 `scripts/DatabaseSetup.java`。需要使用指定 Maven 缓存时，加 `-MavenRepository '你的本地缓存绝对路径'`；已有有效 classpath 文件可加 `-ClasspathFile '文件绝对路径'`。`verify` 需要样例已导入。

流程为：读取 `.env`（进程环境变量优先）→ 检查本机库名 → Flyway 校验并迁移 → 本地随机密码 → 一个 JDBC 事务导入所有样例 → 核对 BCrypt → 提交 → 验证数据和约束。数据库密码与模型密钥不会打印。`scripts/seed-local.sql` 依赖工具在同一连接中准备的临时表，不能直接作为独立 SQL 执行。

Flyway V2—V5 只维护结构；应用启动时仍不自动导入测试数据。执行过的 V1—V5 不要修改，结构变更新增 V6 等版本。若迁移成功而样例导入失败，结构会保留，样例事务回滚；修复后可以重试。

## 6. 向量与业务边界

七个向量是脚本生成的 **16 维 one-hot 测试向量**，模型名 `fixture-one-hot-16-v1`、命名空间 `mock-v1`、`metadata.syntheticEmbedding=true`。它们能检查 pgvector 存取、维度和距离计算，不能验证中文语义检索效果，没有调用真实 Embedding 或 Chat API。

真实模型尚未选定 D，因此存储列使用 `vector` 加维度 CHECK，并通过外键将每个分块绑定到导入任务的模型/维度/命名空间。已为 mock-v1 创建 `embedding::vector(16)` 的 HNSW 部分索引。确定真实模型后，应新增命名空间和对应 `vector(D)` 索引，重新生成全部真实向量；每次查询必须限定模型与命名空间。已有 mock 向量不应复用到 live。

数据库约束已验证：禁止绑定他人订单、拒绝错误向量维度、同一会话最多一个活动运行、同订单最多一张活动工单。外键还能保证会话/运行/确认/工单的客户归属以及确认与工单双向关联。

以下仍需 Java 实现：身份与角色授权、政策资格计算、订单故障码与政策匹配、确认时效及不可变草稿、只有 APPROVED 才允许完成建单、工单状态更新与历史的原子性、乐观锁版本递增、worker 租约、模型调用。约束和样例不等于这些功能已完成。
