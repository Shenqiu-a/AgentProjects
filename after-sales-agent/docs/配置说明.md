# 配置说明与学习指南

日期：2026-10-14。所有命令中的“项目根目录”指 after-sales-agent；“backend 目录”指它的后端子目录。相对上传、日志和 `.env` 路径以进程工作目录为基准。

## 1. 环境与文件位置

| 环境 | 选择方式 | 数据库默认地址 | 应用端口 | 模型模式 |
|---|---|---|---:|---|
| local | 不传 profile，默认生效 | localhost:5432/after_sales | 8080 | MODEL_MODE，默认 mock |
| eval | profiles=eval | localhost:15433/after_sales_eval | 8081 | EVAL_MODEL_MODE，默认 mock |
| test | 测试类 @ActiveProfiles("test") | localhost:15433/after_sales_eval | 随机端口 | 固定 mock |
| prod | profiles=prod | 必须传 DATABASE_URL | 8080，可覆盖 | MODEL_MODE，默认 mock |

eval、test 的默认数据库与 local 隔离。它们共用评测实例时不要同时执行会重置 fixture 的任务；以后可由 Testcontainers 为每组集成测试提供独立 PostgreSQL。

一次选择一个环境。`MODEL_MODE=live` 选择模型模式，不会把 local 自动切换成 prod；`SPRING_PROFILES_ACTIVE=prod` 也不会自动调用模型。

## 2. .env 如何加载

Spring Boot 不会默认加载任意 `.env`。本项目在 local、eval、test 配置中明确声明：

```yaml
spring:
  config:
    import: "optional:file:../.env[.properties]"
```

含义：从 backend 工作目录寻找上一级 `.env`，按照 Java Properties 格式读取；文件不存在时不因缺少该文件而失败。数据库认证仍需提供正确参数。

该文件同时由 Compose 读取，因此请使用 `.env.example` 示范的共同语法：`KEY=value`、单独的注释行、不加 export、不加引号、路径使用 `/`。带 `$`、反斜杠、前后空白或多行的凭证建议改用系统环境变量，避免两种解析器解释不同。

配置优先关系可先记为：命令行/显式 JVM 参数与系统环境变量可以覆盖配置文件；环境专用 YAML 覆盖公共 YAML；import 的本地属性参与对应环境解析。不要依靠 YAML 中的先后行顺序推断所有优先关系。

在 IDEA 中编辑启动配置：Main class 选择现有 AfterSalesAgentApplication，Working directory 设置为 backend。若改变工作目录，需同步调整 import、日志和上传路径。

prod 不导入本地 `.env`，数据库连接从部署环境提供。系统环境变量名为 SPRING_PROFILES_ACTIVE；`.env` 文件内的同名普通属性不能当作真实进程环境变量来假定其已激活 profile。

## 3. 数据库与 Compose

主库服务名 postgres；可选评测库服务名 postgres-eval，两者使用不同 volume。固定镜像标签是 `pgvector/pgvector:0.8.7-pg17-bookworm`，对应官方提供的 PostgreSQL 17 变体。

| 参数 | 作用 |
|---|---|
| POSTGRES_PORT | 主库映射到宿主机的端口，也用于 local 默认 JDBC 地址 |
| POSTGRES_DB | 主库名称，也用于 local 默认 JDBC 地址 |
| DATABASE_USERNAME/PASSWORD | 主库初始化凭证与后端连接凭证 |
| DATABASE_URL | 可选完整 JDBC 地址；存在时优先于主机/端口/库名组合 |
| EVAL_POSTGRES_PORT | 评测库宿主机端口，默认 15433 |
| EVAL_DATABASE_USERNAME/PASSWORD | 评测库独立凭证 |
| EVAL_DATABASE_URL | 可选评测 JDBC 地址 |
| TEST_DATABASE_URL | 集成测试专用覆盖值，不回退使用主库 DATABASE_URL |

Compose 的数据库端口只绑定宿主机 127.0.0.1。当前后端运行在宿主机，所以使用 localhost；将后端容器化后，JDBC 主机名应改为 Compose 服务名，端口使用容器内 5432。

PostgreSQL 镜像的初始化变量只在空数据卷首次初始化时创建账号和库。以后修改 `.env` 密码不会自动更新已有数据库账号，需明确执行账号变更。`docker compose down` 保留数据；不要把带 `-v` 的删除数据卷操作当成普通重启步骤。

启动与检查（项目根目录）：

```powershell
docker compose up -d --wait postgres
docker compose ps
```

检查扩展（先从 backend 启动应用，使 Flyway 执行完成）：

```powershell
docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT extname, extversion FROM pg_extension;"'
```

应能看到 vector。镜像包含扩展文件，V1 迁移在数据库内启用它，这两件事缺一不可。

## 4. 数据源与迁移

Hikari 连接池：最大 10、最少空闲 2（local 为 1），获取连接最多等待 3 秒。JdbcTemplate 查询默认 3 秒超时；未来 AgentRunner 仍要根据剩余 deadline 限制一次执行的总时长。

Flyway 从 classpath:db/migration 加载，启动时校验已执行迁移与文件校验和，禁用 clean，禁用自动 baseline。

第一份迁移 `V1__enable_pgvector.sql` 仅启用扩展。当前 V2—V5 已建立 18 张业务表；不要把业务表通过另一份 schema.sql 重复初始化。本机主库已导入少量开发样例，表用途、账号位置和重建命令见 [数据库与测试数据](./数据库与测试数据.md)。

已执行过的迁移不要随意改写，新增版本表达变化。上线时数据库账号权限与扩展创建权限单独安排；若应用角色没有创建扩展权限，可先由管理员启用 vector。

## 5. Web、会话与日志

- 单文件 10MB、请求总量 11MB；后者给 multipart 元数据预留空间。
- 未知 JSON 字段拒绝，保留响应中显式的 null；DTO 仍需 @Valid 等校验。
- JSESSIONID 采用 HttpOnly、SameSite=Lax；local/eval/test 的 HTTP 环境允许非 Secure，prod 强制 Secure，需 HTTPS。
- 会话配置不代替 SecurityFilterChain；认证、角色、CSRF、JSON 登录与登出仍需实现。
- 仅暴露 Actuator health，隐藏详情；业务 `/api/v1/health` 需自行实现。
- 日志写入 data/logs 或独立 eval 目录，10MB 滚动、保留 7 个周期、上限 100MB。
- local 的业务包为 DEBUG，框架与 AI 库保持 INFO；不得自行打印密钥、Cookie、密码或完整敏感 Prompt。
- requestId/runId 使用 MDC 占位；尚无过滤器和 runner 时显示 none，需要后续代码填入。
- prod 控制台为 ECS JSON，文件日志继续采用文本格式。日志配置统一在 YAML，无额外 Logback XML。

服务端保存 Instant/timestamptz；业务日期按 Asia/Shanghai 的 Clock 计算。Jackson time-zone 不会自动把每个 Instant 改成某种本地日期格式，前端应负责展示时区。

## 6. 自定义 app.* 参数怎样生效

当前只有配置定义。后续建议创建 AppProperties（@ConfigurationProperties(prefix="app")），通过 @ConfigurationPropertiesScan 或 @EnableConfigurationProperties 注册，分组绑定 Duration、DataSize、枚举、整数和嵌套 record。

| 参数组 | 后续读取者 | 应验证的条件 |
|---|---|---|
| app.ai | ModelConfiguration、ModelGateway、EmbeddingGateway | mode 仅 mock/live；live 模型配置齐全；维度与真实结果一致 |
| app.document | DocumentService、Chunker | 文件根目录合法；0 <= overlap < chunk-size |
| app.rag | RetrievalService | 候选数大于等于 top-k；RRF 分母为正；过滤归属与发布版本 |
| app.agent | AgentRunner、ConfirmationService | 预算为正；网络重试计入预算；确认与幂等期限合理 |
| app.worker | 数据库 worker 与执行器 | 有界并发；心跳周期小于租约；有实际实现才启用 |
| app.sse | RunEventService、SSE Controller | 定期心跳；持久化重放；慢客户端断开后可恢复 |
| app.seed | 本地 fixture 初始化器 | 仅 local/eval 等明确环境可启用，不在 prod 初始化演示账号 |
| app.evaluation | EvaluationRunner | 独立数据库/文件/索引；live 明确允许后才可调用 |

Mock 生成模型和 Mock Embedding 也需要 Java 实现。将 MODEL_MODE 写成 mock 不会凭空产生这些类。当前 POM 只有 AI 核心接口，真实 provider 模块应在选择服务商后引入并装配。

live 模式不应缺少配置时自动降级 mock。未来启动校验要检查 CHAT/EMBEDDING 参数、真实维度与索引模型标识；切换模型或维度需要迁移索引。INDEX_NAMESPACE 也必须随模型版本调整，不能混用 mock 与真实向量。

调用观测要区分：聊天模型请求、Embedding 请求、工具执行。`modelCalled=false` 只表示没有实际生成请求，不能据此断言 Embedding 也没有调用。

## 7. 测试与评测

普通 EligibilityService、Chunker 等单元测试不需要 Spring 上下文。需要 PostgreSQL 的集成测试使用 @ActiveProfiles("test")，先启动隔离评测实例，后续也可使用 Testcontainers。

test 配置在 src/test/resources，不进入正式应用的 main 资源。它固定 mock、随机 HTTP 端口、独立上传目录，并禁用后台 worker/评测任务。

eval 配置用于独立进程。主应用 F01 未来可以把任务交给隔离 EvaluationRunner；仅有这份 YAML 还没有实现作业投递或 fixture 重置。

配置生成时未检测到 docker 命令，Docker 启动流程与完整 Compose 解析尚未实测。后续已在本机原生 PostgreSQL 18 完成 pgvector 安装、两库启用和向量运算验证，见 [安装记录](./pgvector安装记录.md)。完整后端启动与 Flyway 历史记录仍需在应用启动时验证；`app.*` 的实际绑定和运行行为也要在实现配置类后验证。

| 现象 | 首先检查 |
|---|---|
| Connection refused | PostgreSQL 是否启动；5432 是否被占用；DATABASE_URL 是否覆盖了端口 |
| 密码认证失败 | .env 是否按正确工作目录加载；账号是否已在旧卷初始化；密码是否真正改到库中 |
| 找不到 vector 扩展 | 是否使用含 pgvector 的服务端安装/镜像；不是只安装 JDBC 驱动 |
| local 仍没有凭证 | IDEA 工作目录是否为 backend；文件是否叫 `.env` 而不是 `.env.example` |
| prod Cookie 不发送 | 是否 HTTPS；是否同源；反向代理与可信转发头是否正确配置 |
| 业务接口 404 | Controller 尚未实现，不能靠 YAML 产生接口 |
| 业务接口要求登录 | 默认 Spring Security 仍在保护，等待实现项目的安全配置 |
| 修改 app.* 看不到行为变化 | 对应 Properties 绑定与使用者是否已经实现 |
